### Core Philosophy (do not break)

- First-party evidence only

- Unknowns must stay visible

- No star ratings or invented claims

- Conflicts and thin fields remain honesty markers

- Fail-closed on access, allergy, or operational guarantees

- Explicit, reader-controlled actions only

### Remove Occasion OS Completely

- Remove the "Occasion OS" button/link from the top action bar

- Remove every reference, link, handoff, or mention of Occasion Operating System, Occasion OS, or Host Plan from this application

- Restaurant Intelligence must stand completely on its own as a restaurant decision tool

### Intelligence Upgrades

Make the ranking and findings significantly smarter and more useful:

- Deepen the situation model so occasion + party composition + guest constraints + lead time + planning load + daypart + spend band more powerfully reshape ranking order and which findings rise first

- Improve multi-layer findings: Critical risks, Watch items, and residual unknowns should be clearer, more actionable, and ranked by decision impact for the specific situation

- Strengthen conflict handling — preserve official conflicts and show the cleanest path to live confirmation without collapsing evidence

- Make thin fields (parking, dress, access honesty, etc.) more useful by showing what the user should verify and why it matters for this situation

- Generate a short, high-quality “Decision Brief” for any restaurant that summarizes fit, residual risk, confirm burden, and recommended next action

- Support partial inputs gracefully — the system should still produce useful ranking and findings even when the situation is incomplete

### Visual Design (High-End)

Transform the current utilitarian interface into a refined, high-end technical instrument:

- Aesthetic: Luxury editorial meets precision decision tool. Deep charcoal / near-black base with refined accents. Soft depth, excellent typography hierarchy, generous but purposeful spacing, progressive disclosure

- Situation console should feel like a premium control surface, not a form

- Ranked findings and case files should feel elegant and scannable rather than dense data tables

- Status indicators for conflicts, thin fields, review freshness, and confirm burden must be clear and sophisticated

- Create beautiful empty states, loading states, and a premium printable “Restaurant Decision Packet”

### Workflow Upgrades

Make the experience smoother, richer, and more useful:

- Improve the situation → ranked findings → case file → decision flow with better progressive disclosure

- Allow the user to refine the situation live and see ranking update intelligently

- Make comparing 2–3 restaurants cleaner and more insightful

- Produce high-quality exportable outputs (Decision Brief + full Case Packet) that feel professional and useful in the real world

### Tone & Voice

Keep the existing precise, honest, slightly dry intelligence voice. Avoid hype, guarantees, or marketing language. The tool should feel like a sharp, trustworthy analyst — not a recommendation engine.
